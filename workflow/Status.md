### Proposals Retained from the Design Drafts

These are working proposals, not settled design. They remain here after the draft documents are removed.

**Scaling projection (area 1).** These estimates are not measured workloads. Refine them into low, expected, and high cases using measured throughput.

| Measure | Factor 100 | Factor 500 | Factor 5,000 |
|---|---|---|---|
| Expected accounts at cutover | About 601,367 | About 3.01 million | About 30.07 million |
| Trades per trading day, before spending and holding constraints | About 84,000 | About 420,000 | About 4.2 million |
| Offline files per year at that firm size | About 8 GB | About 40 GB | About 400 GB |
| Normal-day peak of cash transactions per second | About 6 | About 30 | About 300 |

The factor 100 peak reaches about 18 cash transactions per second on market-shock days, with further bursts after outages. The proposed growth path keeps the same jobs and adds Spark cores or workers, SeaweedFS volume servers, Trino workers, Kafka partitions, and Flink parallelism as needed.

PostgreSQL is the expected first limit: about 330 million Gold rows at cutover and 1.1 billion after seven years at factor 100, and about 1.65 billion at cutover at factor 500. The proposal partitions facts by date at the larger size. At the largest size, consider Delta Gold or a distributed warehouse, keeping dimensions and live tables in PostgreSQL.

**Metadata proposal (area 2).** Each quality rule code would identify a catalog entry with description, owner, severity, and business or technical category.

| Column or field | Bronze | Silver | Gold |
|---|---|---|---|
| `_source_file`, `_record_num` | Yes | Yes | No |
| `_data_date` | Yes | Yes | Yes |
| `_ingested_at` | Yes | Yes | No |
| `_run_id` | Yes | Yes | Yes |
| `_schema_version` | Yes | Yes | No |
| CDC flag and sequence number | Yes | Yes | No |
| `_quality_flags` | No | Yes | Yes |
| `valid_from_ts`, `valid_to_ts`, `is_current` | No | No | SCD2 dimensions |

**Optional additions.** A lockstep publisher mode could keep the stream and daily pipelines in step; JSON Schema files remain the accepted event contract, while a schema registry with Avro is a later option. Full audit logs and broker-only access with personal-data masking remain optional. None blocks the initial build.

## Known Defects

These defects remain in maintained scaffolding or the archived prototype. The comment pass documents them without expanding into the infrastructure rebuild.

| Defect | Where | Cause and Effect |
|---|---|---|
| Silver load deletes earlier batches | `local/archive/prototype-v0/pipelines/dp1/bronze_to_silver.py` | Clears the whole table location before an overwrite, which is the default mode. Loading Batch 2 deletes Batch 1 rows. |
| Unmatched rows are never reported | `local/archive/prototype-v0/pipelines/dp1/landing_to_bronze.py` | Counts unmatched rows after replacing the frame with the union of matched shapes, so unexpected field counts disappear without a warning. |
| Regenerated files are not uploaded | `local/archive/prototype-v0/pipelines/dp1/publish_landing.py` | Skips uploading a file whose name already exists in the bucket. |
| Lateness settings & tax-rate loop in v0 `datagen` | `local/archive/prototype-v0/generator/` | Lateness rates were unwired, and tax-rate generation requested 320 codes from a space of 90. |
| Cast failures in v0 `dp1` | `local/archive/prototype-v0/pipelines/dp1/bronze_to_silver.py` | Failed casts stayed in Silver as NULL, and `_rejected_columns` did not name the failed column. |
| Missing build contexts | `infra/` | Compose files reference `docker/airflow`, `docker/flink`, and `docker/datahub-ingest`, which do not exist yet. |
| Airflow executor and worker conflict | `infra/compose.orchestration.yaml` | The pinned scaffold uses Airflow 2.10.5, not the designed Airflow 3 deployment. `LocalExecutor` runs tasks in the scheduler, but a separate service runs a worker command. |
| Airflow imports cannot seed the provided inputs | `infra/compose.orchestration.yaml`, `data/airflow/variables.yaml.example` | Airflow 2.10.5 connections import does not accept `--conn-description`; variables import reads JSON, not this YAML source. Both commands end with `\|\| true`, so failures can leave setup incomplete with a successful exit. Confirmed against the pinned version's `cli_config.py` and `variable_command.py`. Fix import commands and source conversion during the Airflow rebuild. |
| Unchecked per-key delete failures | `infra/docker/tools/tools/purge.py` | S3 can return per-key `Errors` in a successful delete response. The helper ignores them and counts requested deletions, so it can overcount and repeat forever without progress. The helper also does not validate an empty prefix or batch size; only the CLI rejects an empty prefix. Do not use it for unrestricted cleanup before these checks are added. |
| Incomplete object listings | `infra/docker/tools/tools/ls.py` | The command prints at most 200 objects from the first page and ignores an unpaired argument. If the first page has more than 200 entries but is not truncated, omitted entries have no warning. |
| Smoke-check isolation and cleanup | `infra/docker/tools/tools/smoke.py` | Checks share fixed schema and table names, leave some objects and Trino connections, upload the same Parquet object twice, and retain results between `main()` calls. Run only one copy at a time. |
| PostgreSQL retry deadline is not strict | `infra/docker/bootstrap/bootstrap/run.py` | A connection attempt has no separate connection timeout, so it can exceed the outer retry window. |
| KRaft example identity needs startup validation | `infra/.env.example` | The unchanged example cluster ID has 23 characters and decodes to 17 bytes rather than a 16-byte Kafka UUID. Validate or replace it for a fresh broker with Kafka's CLI; do not change an existing broker's stored identity as a naming chore. No Kafka startup test ran. |
| Small files & slow Spark shutdown | `local/archive/prototype-v0/pipelines/dp1/` | Wrote ~1 Parquet file per date partition (1,800 ~5 KB files at scale 0.02) and blocked while closing the event log against SeaweedFS. |
